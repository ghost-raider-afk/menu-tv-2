# TV Menu 2.0 — план развития

## Принцип анимации

Меню является постоянно открытым информационным экраном, а не последовательностью слайдов. Поэтому основной Motion Engine должен работать как **continuous / ambient motion**:

- весь контент меню виден с первого кадра и остаётся читаемым;
- анимация не строит экран заново и не скрывает строки целиком;
- движение используется для фона, света, глубины, разделов, отдельных строк и цен;
- активные события короткие, между ними есть спокойные участки цикла;
- один и тот же canonical renderer остаётся источником геометрии и содержимого.

Entrance/slide-show модель считается устаревшей и поддерживается только как compatibility-вход для миграции ранее сохранённых профилей.

## Live Player — браузерный вывод меню

Запланировать второй полноценный канал доставки наряду с файловой публикацией:

```text
TV MENU CORE
├── File Publish
│   ├── JPEG fallback
│   └── MP4 при необходимости
└── Live Player
    ├── Browser/Kiosk
    ├── Motion Engine
    ├── realtime updates
    └── player health
```

### Требования

- каждый монитор получает стабильный player URL;
- браузер в kiosk mode показывает тот же canonical screen scene, что редактор;
- публикация изменения может обновлять экран без полной перезагрузки страницы;
- WebSocket используется для realtime-команд и состояния;
- серверная временная шкала является источником времени для анимации;
- player регулярно отправляет heartbeat: online/offline, FPS, version, last sync, current scene;
- при кратком разрыве сети последнее валидное меню продолжает работать локально;
- JPEG остаётся аварийным fallback и независимым каналом публикации.

## Character Story Engine — сюжетная анимация персонажей

После появления browser/live renderer реализовать отдельный слой **Character Story Animation** поверх постоянного меню. Это не обычный motion preset и не переход между экранами: меню остаётся полностью открытым, а персонаж периодически запускает короткую фирменную историю.

Первый референсный персонаж — **рыбка из бокала**. Базовая история:

```text
рыбка находится в бокале
        ↓
оживает и выплывает
        ↓
плавает по безопасной траектории поверх/между элементами меню
        ↓
сверху появляется крючок
        ↓
рыбку подхватывают и тянут вверх
        ↓
у верхней границы она срывается
        ↓
возвращается по траектории обратно в бокал
        ↓
переход в спокойное состояние
```

### Архитектура

```text
Canonical Menu Scene
        +
Ambient Motion Engine
        +
Character Story Engine
        ↓
Browser Live Player
```

Story Engine должен работать как независимый событийный слой и не менять содержимое/геометрию самого меню.

### Сущности

- `CharacterAsset` — графика/спрайт/SVG персонажа и вспомогательных объектов;
- `CharacterAnchor` — исходная и конечная точка персонажа на конкретном экране, например положение рыбки в бокале;
- `StoryPreset` — готовая история;
- `StoryTimeline` — последовательность фаз и событий;
- `MotionPath` — траектория движения по координатам canonical scene;
- `StoryProp` — крючок, пузырьки, сеть и другие объекты истории;
- `LayerTrack` — порядок отображения перед/за таблицей и декоративными слоями;
- `SafeZone / ExclusionZone` — области, в которых персонаж не должен надолго перекрывать цены, названия и другие критичные элементы.

### Требования к поведению

- история запускается как редкое событие поверх спокойного ambient motion, а не непрерывно;
- задаётся интервал запуска и допустимая случайность внутри интервала;
- пользователь может включать одну историю, фиксированный набор или случайную ротацию историй;
- персонаж всегда имеет гарантированную точку возврата в исходное состояние;
- траектории учитывают реальные размеры/геометрию выбранного монитора;
- критичные зоны меню автоматически учитываются как зоны ограничения движения/перекрытия;
- story timeline поддерживает pause/resume/seek и в будущем синхронизацию по server clock;
- сложные сцены должны использовать compositor-friendly SVG/Canvas/Web Animations API и не снижать читаемость меню;
- при `prefers-reduced-motion` и аварийном fallback сюжетные сцены не запускаются;
- для каждого сюжета задаются длительность, частота, интенсивность, слой и допустимые зоны движения;
- Story Engine проектируется так, чтобы в будущем один персонаж мог переходить между viewport нескольких экранов одной `ScreenGroup`.

### Полный Story Pack для рыбки

Сценарии должны храниться как независимые `StoryPreset`, чтобы администратор мог включить один сюжет, несколько выбранных сюжетов либо случайную ротацию.

#### Спокойные / ambient-сценарии

1. **Короткое плавание** — рыбка оживает в бокале, выплывает, делает спокойный круг и возвращается на исходное место.
2. **Исследование меню** — проходит по нескольким свободным зонам экрана, ненадолго задерживается возле разделов и возвращается.
3. **Свободное плавание** — выбирается один из нескольких заранее безопасных маршрутов, после чего рыбка гарантированно возвращается к anchor.
4. **Восьмёрка** — рыбка описывает плавную восьмёрку или круговой маршрут между блоками меню и возвращается в бокал.
5. **Патруль разделов** — последовательно проплывает вдоль нескольких заголовков разделов, не перекрывая товары и цены.
6. **Тихое пробуждение** — рыбка только слегка оживает в бокале: движение хвоста, короткий поворот, небольшой выход наружу и возврат без большого маршрута.
7. **Пивная пена** — рыбка появляется из области бокала/пены, делает короткий нырок наружу и снова скрывается в исходной зоне.
8. **Пузырьки** — рыбка выпускает или сопровождает цепочку пузырьков, делает небольшой маршрут и возвращается.

#### Игровые сюжетные сценарии

9. **Пузырёк** — один пузырёк уходит из бокала, рыбка преследует его через меню, пузырёк лопается, рыбка возвращается.
10. **Крючок — ловля и срыв** — базовая фирменная история: рыбка выплывает, появляется крючок, её ловят и тянут вверх, у верхней границы она срывается и возвращается в бокал.
11. **Побег от крючка** — крючок появляется до захвата, рыбка замечает его, резко меняет траекторию, уходит от него и прячется обратно.
12. **Крючок-приманка** — рыбка подплывает к приманке, несколько раз осторожно приближается и отступает, после чего отказывается клевать и уплывает домой.
13. **Почти поймали** — крючок на мгновение цепляет рыбку, она делает рывок, освобождается раньше подъёма и уходит по быстрому маршруту.
14. **Сеть** — сбоку или сверху появляется сеть, рыбка избегает захвата, проходит через безопасный коридор и возвращается.
15. **Прятки** — рыбка уходит за декоративный слой/раздел, через короткую паузу выглядывает из-за него и затем возвращается в бокал.
16. **Резкий побег** — спокойное плавание внезапно прерывается появлением крючка или другого объекта; рыбка резко уходит в сторону, затем постепенно успокаивается и возвращается.
17. **Ложная тревога** — сверху появляется тень/крючок, рыбка готовится бежать, объект исчезает, рыбка делает круг и возвращается без погони.
18. **Двойной крючок** — первый крючок отвлекает рыбку, второй появляется с другой стороны; рыбка проходит между ними и уходит обратно невредимой.

#### Световые и фирменные сценарии

19. **Золотая волна** — световой проход Motion Engine идёт по меню, рыбка просыпается и плывёт вслед за волной, затем возвращается.
20. **Золотой блик** — короткий shimmer проходит по разделам, рыбка следует за бликом и исчезает обратно в бокале после завершения прохода.
21. **Световой след** — за рыбкой остаётся короткий декоративный след/частицы, которые быстро затухают и не мешают чтению меню.
22. **Рыбка-маскот** — персонаж периодически оживает, машет хвостом, делает узнаваемый короткий маршрут и возвращается; это базовый фирменный idle-story для редкого повторения.
23. **Приветствие** — рыбка выплывает из бокала, делает короткий разворот к зрителю/центру сцены, затем возвращается; использовать редко, без постоянного повторения.
24. **Ночная/спокойная история** — минимальная амплитуда, медленное плавание и мягкие пузырьки для менее активного режима отображения.

#### Промо-сценарии

25. **Промо-маршрут** — рыбка проходит к заданной позиции или разделу, делает вокруг него короткий круг/акцент и возвращается, не перекрывая цену.
26. **Новинка** — рыбка подплывает к позиции, отмеченной как новинка, коротко задерживается рядом и уходит.
27. **Акцент на разделе** — рыбка проходит к конкретному заголовку раздела, после чего Motion Engine запускает мягкий glow этого раздела.
28. **Ценовой акцент** — рыбка подводит взгляд к выбранной цене, но не заходит на её safe zone; после короткого price pulse возвращается.
29. **Маршрут по акциям** — если на экране несколько промо-позиций, рыбка последовательно проходит рядом с каждой из них по безопасной траектории.
30. **Промо-пузырёк** — пузырёк выступает как проводник к промо-позиции, рыбка следует за ним, акцентирует товар и возвращается.

#### Сценарии для будущих групп экранов

31. **Переход между экранами** — рыбка выплывает с одного TV, пересекает границу viewport и продолжает движение на соседнем экране по общей master timeline.
32. **Панорамное плавание** — один длинный маршрут проходит через всю `ScreenGroup`, после чего рыбка возвращается на домашний экран и в исходный бокал.
33. **Крючок через группу** — рыбка перемещается между несколькими экранами, крючок преследует её в координатах общего виртуального холста.
34. **Групповая золотая волна** — рыбка следует за общей световой волной, которая проходит последовательно через все телевизоры группы.
35. **Побег на соседний экран** — угроза появляется на домашнем TV, рыбка уходит на соседний экран, пережидает там и затем возвращается.
36. **Промо-путешествие по группе** — рыбка последовательно привлекает внимание к промо-зонам на разных телевизорах одной группы.

### Правила Story Pack

- сюжет с крючком, сетью и другими активными объектами считается редким событием и не должен запускаться слишком часто;
- спокойные истории могут использоваться чаще, но между ними обязательно остаётся период полностью спокойного меню;
- ни один сценарий не должен надолго закрывать название продукта, объём или цену;
- промо-сценарии получают привязку к конкретной строке/разделу через идентификатор элемента, а не через фиксированные экранные координаты;
- все сценарии должны автоматически пересчитывать путь при изменении геометрии меню;
- у каждого сценария есть `home anchor`, аварийный возврат и максимальное время нахождения персонажа вне исходной зоны;
- истории можно ранжировать по интенсивности: `calm`, `normal`, `active`, чтобы администратор мог ограничивать характер движения;
- в библиотеке должна быть возможность отключить отдельные истории без удаления их конфигурации;
- для случайной ротации задаются веса вероятности, минимальный интервал повторения одного сюжета и общий cooldown;
- групповая версия использует общий server clock и никогда не запускает отдельную независимую копию истории на каждом TV.

### Редактор

В Motion Studio предусмотреть отдельный режим **«Сюжеты / Персонажи»**:

- выбор персонажа;
- выбор StoryPreset;
- реальный экран в мини-плеере;
- визуальное задание anchor и маршрута;
- настройка safe/exclusion zones;
- частота запуска;
- случайная ротация историй;
- длительность и интенсивность;
- слой отображения;
- ручной запуск истории для предпросмотра;
- timeline с фазами истории и scrubbing.

Первая версия не должна становиться полноценным сложным видеоредактором: основной сценарий — готовые профессиональные StoryPreset с возможностью безопасно настроить маршрут, частоту и интенсивность.

## Синхронизированные группы экранов

После Live Player реализовать сущность `ScreenGroup` для нескольких физических телевизоров, работающих как единая сцена.

Пример:

```text
Location
└── ScreenGroup «Бар»
    ├── Screen 1
    ├── Screen 2
    └── Screen 3
```

Для трёх экранов 1920×1080 редактор группы получает виртуальный холст 5760×1080. Каждый player отображает только собственный viewport общей сцены.

### Master Timeline

```text
Group Motion Studio
        ↓
Master Timeline / Server Clock
        ↓
 ┌──────┼──────┐
 ↓      ↓      ↓
TV 1   TV 2   TV 3
```

Требования:

- одна master timeline для всей группы;
- одинаковая позиция цикла определяется серверным временем, а не моментом открытия browser tab;
- поздно подключившийся player сразу переходит на текущую позицию сцены;
- периодическая оценка clock offset и drift correction;
- состояние синхронизации отображается в панели: online, FPS, clock offset, drift;
- переходящие между экранами объекты рассчитываются в координатах общего виртуального холста;
- individual tracks позволяют при необходимости анимировать только конкретный экран;
- отдельная библиотека group-motion presets: wave, panorama, domino, ripple, cross-screen slide, center pulse, promo journey и другие;
- Character Story Engine в group mode использует ту же master timeline и может переносить персонажа между экранами без перезапуска истории.

## Порядок реализации

1. Continuous Motion Engine для постоянно открытого одиночного меню.
2. Подключение Motion Engine к конечному browser/live renderer.
3. Single-screen Live Player: kiosk URL, realtime update, heartbeat, offline cache.
4. Character Story Engine для одиночного экрана + первый Story Pack с рыбкой.
5. Server clock и drift correction.
6. `ScreenGroup` + виртуальный общий холст.
7. Group Motion Studio + синхронизированная master timeline.
8. Поддержка cross-screen Character Story для групп экранов.
9. Мониторинг группы и диагностика синхронизации.

Live Player, Character Story Engine и ScreenGroup должны добавляться без удаления существующей JPEG/SFTP публикации: каналы должны сосуществовать, а статический JPEG оставаться независимым fallback.
