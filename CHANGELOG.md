# История версий ТВ МЕНЮ 2

## [1.4.2] - 2026-08-24

### Интерфейс
- Контекстное подменю теперь сворачивается после выбора пункта одинаково во всех разделах и не переносит временное состояние сворачивания между независимыми разделами.
- Заголовок вкладки браузера формируется из сохранённого названия приложения и текущего маршрута и обновляется сразу после изменения названия без перезагрузки страницы.
- Из «Настроек» удалён дублирующий блок журнала: «Журнал событий» остаётся единственным отдельным разделом и источником истории для колокольчика.
- Мобильное подключение ТВ сохраняет полноценное оформление и последовательный flow при переходе через постоянную SPA-оболочку, включая полноэкранный QR-сканер.

### Анимация
- Motion Studio упрощён до одного явного профиля акцента плашки «Акция» вместо набора из 20 пресетов; обычные строки продукции по умолчанию остаются неподвижными.
- Плашка «Акция» остаётся одной SVG-группой `path + text`, но теперь владеет независимым motion-эффектом и glow-каналом, не наследуя анимацию товарной строки.
- Live Preview жёстко ограничивает фон, Entity и визуальные эффекты геометрией выбранного монитора и не допускает выхода изображения за границы кадра.
- Добавлена независимая бегущая строка с настройками текста, положения, скорости, размера шрифта, цвета текста и фона.

### TV Player
- Бегущая строка передаётся в `player-context`, рендерится отдельным слоем поверх меню и Entity и сохраняется в offline shell вместе с последней рабочей версией экрана.
- Motion-профиль, Entity и бегущая строка остаются независимыми слоями, поэтому изменение одного механизма не захватывает transform/appearance другого.

### Проверки
- Добавлены и обновлены regression-тесты независимого motion ownership плашки, валидного catalog-backed Live Preview, route-aware title и мобильного подключения ТВ после SPA-навигации.
- Релизный набор проверен через node/unit, Chromium browser/visual и clean-install smoke до фиксации финального номера версии.

## [1.4.1] - 2026-08-24

### Подключение ТВ
- Срок жизни QR-кода и резервного 6-значного кода сокращён с 10 до 2 минут; значение остаётся управляемым через `DEVICE_ACTIVATION_TTL_MINUTES`.
- На экране ТВ добавлен живой обратный отсчёт по серверному `expires_at`; после истечения QR и резервный код скрываются и автоматически заменяются новой активацией.
- При временной потере связи просроченный QR не отображается как действующий; Player повторяет получение новой активации после восстановления соединения.
- Мобильная страница администратора переработана в последовательный flow «ТВ → Торговая точка → Монитор» с крупными touch-targets и одним активным шагом.
- QR-сканер открывается полноэкранно; используется нативный `BarcodeDetector`, а для Safari/iPhone добавлен локальный fallback на `jsQR` без внешнего CDN.
- Резервный код оставлен как понятный fallback «Не получается отсканировать? Ввести код».

### Обновление
- Installer `1.3.3` переводит только прежнее каноническое значение `DEVICE_ACTIVATION_TTL_MINUTES=10` на `2`, сохраняя явно настроенные пользователем нестандартные значения.
- Добавлены unit/browser regressions мобильного flow, fullscreen scanner, Safari fallback, countdown и автоматической ротации QR.

## [1.4.0] - 2026-08-24

### Scene Entity
- Добавлен независимый Scene Entity contract и persistence (`entity_json`) вне Motion profile.
- Добавлен Entity Editor v1: PNG/WebP asset, visibility, X/Y, width, scale, rotation, depth, opacity, выравнивание, drag/resize в каноническом пространстве 1920×1080.
- Entity рендерится отдельным слоем в Live Preview и `/player`, передаётся через player context и кэшируется для offline playback.

### Анимация бокала
- Для `beer-glass` добавлен независимый `beer-glass-behavior` SceneProgram со схемой `IDLE → SOFT_EVENT → IDLE → SPECIAL_SCENE → IDLE`.
- Динамическая анимация применяется только к внутреннему motion-wrapper, поэтому сохранённые пользовательские position/scale/rotation остаются владельцем внешнего Entity transform и не конфликтуют с runtime.
- WAAPI serializer поддерживает renderer-neutral rotation; Entity runtime автоматически перепривязывается после замены DOM.

### Миграция и проверки
- Добавлена миграция `009-scene-entity` для существующих установок.
- Добавлены regression-тесты Scene Entity, Beer Glass behavior, TV Player binding и offline cache.
- Финальный набор изменений прошёл node/unit, Chromium browser/visual и clean-install smoke.

## [1.3.5] - 2026-08-24

### Архитектура анимации
- Motion Engine переработан в renderer-agnostic v3 без изменения сохранённого пользовательского `motion_version: 2`.
- Scene Graph отделён от DOM/SVG и использует opaque render targets, логические layers, depth и явный transform ownership.
- DOM/SVG binding вынесен в отдельный `dom-scene-adapter`; canonical menu renderer больше не зависит от Motion Runtime.
- Текущая анимация разделена на независимые SceneProgram `menu-motion` и `atmosphere`.
- Добавлен `Scene Composer`, который до запуска driver проверяет уникальность программ и запрещает конкурирующее владение `transform`, `opacity` и `appearance` одного scene node.
- Добавлен `Scene Runtime`, объединяющий независимые compilers в один master timeline и единый lifecycle `play/pause/replay/seek/destroy`.
- Motion state хранит числовые `x/y/z`, scale, opacity, brightness/glow и семантический timing без CSS-строк; CSS serialization выполняется только WAAPI driver.
- WAAPI driver записывает только явно заявленные track claims, поэтому программа не может незаметно менять чужой канал.
- После перерендера или смены монитора preview player проверяет актуальность scene targets и автоматически перестраивает Scene Graph вместо использования ссылок на удалённые SVG-узлы.

### Будущая 2.5D / 3D сцена
- Scene Graph уже содержит независимый слой `entity`, но default menu/atmosphere compilers намеренно не управляют будущей Live Entity.
- Архитектура допускает будущие Pixi/Three/WebGPU drivers и отдельный entity behavior compiler без переделки SVG renderer, Scene Graph и Timeline.
- Performance/quality ограничения, device tiers, asset budgets и GPU-зависимости в этой версии намеренно не вводятся.

### Проверки
- Добавлены regression-тесты Scene Composer ownership, независимого вызова compilers, Scene Runtime и выборочной WAAPI serialization по claims.
- Сохранены Chromium-проверки существующей анимации и единой плашки «Акция» после архитектурной переработки.
- Добавлен Chromium regression на замену DOM preview: после повторного render анимация обязана перепривязаться к новым scene targets, а старые targets не должны сохранять активные анимации.

## [1.3.4] - 2026-08-24

### Анимация
- Плашка «Акция» анимируется как отдельная единая SVG-группа `path + text` и больше не получает вложенное масштабирование от родительской строки.
- Содержимое товарной строки и плашка используют одну фазу Motion Engine, поэтому при `scale` сохраняют синхронность без двойного transform.
- Добавлен реальный Chromium regression-тест, проверяющий, что форма и текст плашки не получают независимых анимаций.

### Меню
- Отображение Тары приведено к визуальному языку основной таблицы без отдельных карточек, рамок и скруглённых контейнеров.
- Сохранено размещение до двух позиций Тары в одной строке; цена использует ту же типографику целой и дробной части, что продукция.

### Интерфейс
- Восстановлено автоматическое сворачивание контекстного подменю после выбора пункта в «Каталоге» и «Настройках».
- В «Каталоге» сохранён один пункт подменю «Продукция».
- В «Журнал событий» добавлена кнопка «Очистить журнал» с подтверждением; после очистки сохраняется одна audit-запись с количеством удалённых событий.

## [1.3.3] - 2026-08-24

### Каталог
- Ошибка дубликата теперь указывает тип записи и точное конфликтующее название продукции или тары.
- При конфликте CSV-импорта сообщение дополнительно содержит номер строки и способ исправления.
- Точное сообщение сохраняется в журнале событий категории «Каталог» вместо безымянного «Запись с таким названием уже существует».

## [1.3.2] - 2026-08-24

### Инфраструктура
- Полностью удалены жёсткие CPU-квоты контейнеров приложения, PostgreSQL и SFTPGo; Docker снова распределяет доступный CPU без искусственного ограничения.
- Ограничения памяти и количества процессов сохранены для всех трёх постоянных сервисов.

### Обновление
- Установщик `1.3.2` удаляет устаревшие `APP_CPU_LIMIT`, `DB_CPU_LIMIT` и `SFTP_CPU_LIMIT` из существующего `.env` до применения Docker Compose.

### Проверки
- CI запрещает возвращать `cpus:` в `compose.yaml` и любые `*_CPU_LIMIT` в `.env.example`, а также проверяет очистку старого `.env` без удаления memory/pids-настроек.

## [1.3.1] - 2026-08-23

### Безопасность и надёжность
- Доступ Traefik к Docker API переведён на read-only socket proxy; прямое подключение Traefik к Docker socket исключено.
- Активация ТВ защищена ограничением частоты запросов и очисткой истёкших активаций; изменяющие состояние API проверяют Origin.
- Контейнеры получили лимиты ресурсов, минимальные capabilities и неизменяемые digest внешних образов.

### Обновление и данные
- Добавлен журнал `schema_migrations`; миграции выполняются транзакционно и ровно один раз.
- Обновление создаёт резервную копию до миграции `.env`; rollback точно восстанавливает PostgreSQL, `.env` и конфигурацию proxy.
- Версия установщика отделена от версии приложения и публикуется тегом `installer-vX.Y.Z`.

### TV Player
- Offline cache хранит последний рабочий экран и не затирается ошибочным ответом сервера.
- Player context стал компактнее и поддерживает conditional refresh, сокращая ненужные запросы и передачу данных.

### Каталог
- «Цена 1,5 л» явно обозначена как расчётная в интерфейсе и CSV и никогда не импортируется как самостоятельное значение.
- CSV preview вынесен в отдельный frontend-модуль без изменения атомарного импорта.

### Интерфейс и архитектура
- Renderer разделён на model/layout и SVG-модуль при сохранении одного канонического renderer для preview и JPEG.
- Настройки редактора вынесены из перекрывающих popover в адаптивную in-flow панель.
- Добавлены клавиатурный focus, увеличенные touch-targets и адаптация интерфейса при увеличении до 200%.

## [1.3.0] - 2026-08-23

### Добавлено
- Подключение телевизора через QR-код и 6-значный резервный код с долгоживущей Device Session.
- Offline-first TV Player: ранее подключённый монитор продолжает показывать сохранённое меню при потере Интернета.
- Двухэтапный CSV-импорт базы продукции с предпросмотром, исправлением строк на лету и атомарным применением.

### Исправлено
- Плашка «Акция» собирается как единая SVG-группа, чтобы фон и надпись масштабировались одной структурой.
- Тестовый контракт Device Player разделяет имя монитора и метку устройства.
- Тестовое окружение включает обязательные DEVICE_* параметры.

### Инфраструктура
- Единственная постоянная ветка проекта — `main`.
- Версия проекта берётся из `package.json`.
- Стабильные версии публикуются тегом `vX.Y.Z` и GitHub Release только после полного CI.
- После успешного релиза GitHub Actions удаляет все ветки, кроме `main`.
- Установщик и обновлятор используют последний стабильный GitHub Release, а не HEAD ветки.
- Старый `.installer-ref` больше не выбирает ветку обновления и удаляется при переходе на release-схему.
