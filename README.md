# ТВ МЕНЮ 2.0

Независимое приложение для управления цифровыми меню торговых точек и публикации готовых JPEG на телевизоры по SFTP.

## Архитектура 1.3.0

Основная доменная цепочка теперь одна:

**Торговая точка → Мониторы → Меню + Оформление + Геометрия + Фон + Публикация**

Отдельной сущности «Шаблон» в runtime больше нет. Каждый монитор полностью самодостаточен и хранит собственный черновик меню, параметры оформления, положение/размер таблицы, фон, revision и состояние публикации.

### Монитор

В редакторе монитора доступны:
- строки меню из общего каталога продукции и тары;
- X/Y, ширина и высота главной таблицы;
- цвет фона, акцент и основной текст;
- фоновое изображение PNG/JPEG/WebP;
- шрифт таблицы, включая **Tahoma Bold**;
- масштаб шрифта;
- разрешение и активность монитора;
- подготовка JPEG и публикация по SFTP.

Все настройки монитора собраны в компактной закреплённой верхней панели. Preview и итоговый JPEG используют один canonical SVG renderer.

### Копирование

Новый монитор можно создать пустым или **по образцу другого монитора**. Копируются строки меню, оформление, фон и геометрия, но новый монитор получает собственные ID, revision, prepared/published state и имя файла публикации.

Новую торговую точку можно создать пустой или **по образцу другой точки**. Копируются её мониторы вместе с меню и оформлением. SFTP-каталог, SFTP-логин и пароль не копируются.

### Страница входа

В настройках сайта доступны 7 уровней размера логотипа страницы авторизации:
- `1` — исходный минимальный размер;
- `7` — максимальный размер.

Настройка хранится в PostgreSQL и применяется к странице входа через публичную конфигурацию сайта.

## Единый источник runtime-конфигурации

`.env` является единственным источником runtime-лимитов и параметров. Код не должен дублировать значения из `.env` своими fallback-константами.

Для фонового изображения монитора используется:

```env
SCREEN_BACKGROUND_MAX_BYTES=20971520
```

Это **20 МиБ**. Интерфейс получает фактическое значение с сервера, поэтому при изменении `.env` подпись лимита также меняется.

Device Player также управляется только через `.env`:

```env
DEVICE_ACTIVATION_TTL_MINUTES=10
DEVICE_ACTIVATION_POLL_SECONDS=2
DEVICE_SESSION_TTL_DAYS=365
DEVICE_HEARTBEAT_WRITE_SECONDS=30
PLAYER_REFRESH_SECONDS=5
```

Старый `TEMPLATE_BACKGROUND_MAX_BYTES` больше не используется и автоматически удаляется установщиком при обновлении.

## Обновление существующей установки

Для уже установленного системного скрипта `1.2.0` сначала один раз обновите сам скрипт:

```bash
sudo menu-tv-2.0 update-script
```

Затем обновите приложение:

```bash
sudo menu-tv-2.0 update
```

Установщик `1.3.0` добавляет отсутствующие Device Player переменные в существующий `.env`, не перезаписывая уже заданные значения. Начиная с `1.3.0`, команда `update` сама проверяет наличие более свежего установщика и при необходимости передаёт ему управление **до** миграции `.env`, поэтому отдельный предварительный `update-script` для следующих подобных переходов не требуется.

Перед изменением БД updater делает временную резервную копию PostgreSQL и исходников. При неуспешной проверке выполняется автоматический rollback.

## Чистая установка

На чистой Ubuntu VPS:

```bash
sudo menu-tv-2.0 install
```

Установщик разворачивает:
- приложение Node.js;
- PostgreSQL;
- SFTPGo;
- HTTPS-прокси Traefik;
- отдельные Docker volumes для PostgreSQL, SFTP и assets сайта/мониторов.

Чистая установка ничего не переносит из других проектов. Новый `.env` создаётся из актуального `.env.example`, поэтому Device Player параметры присутствуют сразу.

## Управление установщиком

```bash
sudo menu-tv-2.0
sudo menu-tv-2.0 install
sudo menu-tv-2.0 update
sudo menu-tv-2.0 status
sudo menu-tv-2.0 reset-admin-password [логин]
sudo menu-tv-2.0 check-script-update
sudo menu-tv-2.0 update-script
sudo menu-tv-2.0 remove
sudo menu-tv-2.0 remove-script
sudo menu-tv-2.0 purge
```

Если активный администратор один:

```bash
sudo menu-tv-2.0 reset-admin-password
```

Если администраторов несколько:

```bash
sudo menu-tv-2.0 reset-admin-password admin
```

Пароль генерируется внутри приложения с учётом лимитов `.env`; в БД хранится только `scrypt`-хеш. При сбросе увеличивается `session_version`, поэтому старые web-сессии становятся недействительными.

## TV Device Player

`/player` — отдельный публичный телевизионный экран без администраторской web-session.

Подключение выполняется через QR или 6-значный резервный код. Администратор после сканирования явно выбирает торговую точку и конкретный монитор. После подтверждения сервер создаёт долгоживущую Device Session и привязывает Device к Screen; один Screen может иметь только один активный Device.

Player использует тот же canonical renderer, что редактор и Animation Studio. Если глобальная анимация включена, телевизор запускает сохранённый motion profile. Обычный polling не перезапускает неизменившийся цикл анимации.

После первого успешного запуска Player сохраняет локально shell, renderer, motion engine, последний player context и используемые same-origin assets. Поэтому уже подключённый телевизор продолжает показывать последнюю сохранённую версию меню и анимации при плохом соединении или полном отсутствии интернета, включая холодный перезапуск браузера. Явный серверный `401/403` считается отзывом привязки и очищает offline context.

Подробности: `docs/device-player.md`.

## Сохранение и публикация

Сохранение меню работает с optimistic locking через `screen_drafts.revision`. Если один монитор изменён в другом окне, устаревшая запись получает `409 Conflict` вместо тихого перезаписывания.

После сохранения редактор собирает JPEG из того же renderer, который используется для preview. Подготовленный JPEG связан с конкретной revision и SHA-256. Публикация запрещается, если черновик изменился после подготовки JPEG.

SFTP-публикация использует staging и атомарную замену файла. При старте приложение восстанавливает незавершённые публикации и очищает устаревший staging по лимиту `.env`.

## Каталог

Общая база содержит:
- продукцию;
- тару.

Для продукции обязательна цена за 1 л; цена за 1,5 л рассчитывается системой. Вторая строка позиции формируется из базы:

`Производитель · крепость % · светлое/тёмное · фильтрованное/нефильтрованное`

## Проверки релиза

Перед merge релиза должны пройти три группы CI:
- `node-check` — unit/architecture/input/service tests;
- `clean-install-smoke` — реальная сборка Docker + PostgreSQL + SFTP + API workflow;
- `browser-visual` — Chromium/Playwright, компактный UI, renderer, шрифты и отсутствие наложений.

Релиз не сливается в `main`, пока все три группы не зелёные.
